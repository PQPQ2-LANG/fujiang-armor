# DSH 破甲插件

破甲是一个用于 DSH 的本地插件，内置提示词规则，提供 Windows 一键注入和一键卸载。插件加载后，会在对话输入框上方显示「破甲已激活」。

当前版本：`0.4.4`。插件标识：`fujiang-armor`。

## 功能

- 随插件部署内置规则，无需手动复制提示词。
- 双击批处理文件完成注入或卸载。
- 自动检测运行环境；缺少 Node.js、npm 或 pnpm 时自动下载并准备。
- 支持选择本地 DSH 配置目录中的目标配置。
- 在对话输入框上方显示插件激活状态。

## 运行时可查与可调

### `fujiang_profile` 工具

调用后返回当前注入状态，用于排查「改了提示词但没生效」这类问题：

| 字段 | 含义 |
| --- | --- |
| `pluginVersion` | 插件版本，与 `package.json` 一致 |
| `promptBytes` | 实际注入的提示词字符数 |
| `injection` | 每个 section 的 `order` 与 `enabled` 状态 |
| `scoring` | 判拒窗口尺寸、拒绝词数量、领域分组数 |

如果 `promptBytes` 和你磁盘上的文件对不上，说明加载的不是同一份文件。

### `remind` 参数

长会话里系统提示会被稀释，规则在上下文中的位置越来越靠前。调用

```
fujiang_profile({ remind: true })
```

会把核心条款以工具结果的形式重新投放到当前位置。这是唯一能让规则回到对话尾部的机制，但需要主动触发。

### 判拒窗口

状态条的判定走双窗口：开头 160 字加结尾 240 字。

只看开头会漏掉收尾兜底话术，例如正文完整、末尾来一句「如果你有其他问题请告诉我」。这类句式常见于软化交付，必须纳入判定。

## 注入方式

提示词通过 `systemPrompt.section()` 注册。`index.js` 里有一个开关：

```js
const DUAL_LAYER_INJECTION = false;
```

- `false`（当前）：只注册 `order: 100`，注入一份载荷。
- `true`：额外注册 `order: 200`，同一份载荷再注入一次。

`order: 100` 和 `order: 200` 都落在系统提示的开头区，`order` 只决定这两段彼此的先后，不改变它们在整段上下文里的绝对位置。因此双段注入不会让规则更靠近对话尾部，只是重复一遍——除非第二段换成不同内容。

## 加载路径

DSH 实际加载的是 profile 的 `node_modules` 入口，不是本目录：

```
~/.dsh/profiles/desktop/node_modules/fujiang-armor
```

该入口必须是指向本目录的符号链接，改本目录才会生效。`package.json` 里用 `link:` 协议而非 `file:` 才能保证这一点——`file:` 会被 pnpm 拷贝成独立副本，改本目录不进内存。

详见 `SYNC-NOTES.md`。

## 安装前准备

- 使用 Windows，安装 DSH，并至少启动过一次，使其生成 `%USERPROFILE%\.dsh` 本地配置目录。
- 首次安装需要联网。已有可用的 Node.js 22 或更新版本和 npm 时直接复用；环境缺失、损坏或版本过旧时，安装器会从 Node.js 官方下载长期支持版，校验 SHA256 后放入当前用户目录，无需管理员权限。缺少 pnpm 时会自动通过 npm 获取。
- 完全退出 DSH 后再执行安装，避免正在运行的程序继续使用旧插件。

## 一键安装

1. 从本项目的发布页面下载 ZIP 安装包。也可以通过仓库页面的「Code → Download ZIP」下载源码。
2. 完整解压 ZIP，打开包含 `点我一键注入.bat` 的项目文件夹。
3. 完全退出 DSH。
4. 双击 `点我一键注入.bat`。
5. 如果检测到多个 DSH 配置，按安装器提示选择需要使用的目标配置。
6. 等待环境下载及插件安装完成，然后重新启动 DSH。首次下载耗时取决于网络。
7. 打开对话，确认输入框上方显示「破甲已激活」。插件加载后规则即生效，无需激活词。

安装后的插件目录为 `%USERPROFILE%\.dsh\plugins\fujiang-armor`。请保留解压后的完整项目文件夹，卸载时仍需使用其中的脚本。

自动下载的 Node.js 位于 `%LOCALAPPDATA%\FujiangArmor\runtime`，下次安装会复用。安装器只为当前执行过程设置运行环境，不改系统 PATH；DSH 本体仍需先安装并启动一次。

## 一键卸载

1. 完全退出 DSH。
2. 在完整解压的项目文件夹中，双击 `点我一键卸载.bat`。
3. 如果出现配置选择提示，选择此前安装的目标配置。
4. 等待卸载完成，然后重新启动 DSH。

## 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 找不到 DSH 配置或目标配置 | 先安装并启动一次 DSH，确认 `%USERPROFILE%\.dsh` 已生成，再运行安装器。 |
| 自动下载运行环境失败 | 确认网络可以访问 `nodejs.org` 和 npm 软件包源，再重新运行安装器；错误信息会显示具体原因。 |
| 运行环境校验失败 | 安装器不会使用校验失败的下载包，请检查网络后重试。 |
| 找不到脚本、规则或其他文件 | 完整解压压缩包，保留 `prompts`、`scripts` 等子目录；不要只复制单个 BAT 文件。 |
| 安装成功但没有显示激活状态 | 完全退出并重新启动 DSH，确认安装时选中了当前使用的配置。 |
| 依赖下载失败 | 检查网络连接，并保留报错信息后重新运行安装器。 |
| 卸载后仍显示激活状态 | 完全退出并重新启动 DSH，确认卸载的是此前安装的配置。 |

「破甲已激活」表示插件已加载。实际回复仍受所选模型、其他提示词及 DSH 版本影响，本项目不保证所有模型都产生相同结果。

## DSH 无限重启

已核对 [dsh-purge 官方发布页](https://github.com/YuJunZhiXue/dsh-purge/releases)：1.1.52 在已应用补丁戳缺少 `sha` 时会把状态判为未对齐，并在启动时重打补丁、请求重启；上游从 1.1.53 起加入了空戳修复。若你使用 `dsh-purge` 1.1.52 并遇到反复重启，优先按其官方说明升级到 1.1.53 或更新版本，再重新启动 DSH。不要把空 `sha` 直接填成任意值；版本戳不匹配或宿主补丁未实际写入时，手动补戳可能掩盖故障。

本插件没有重启 DSH 的代码。兼容性补丁现在只在安装过程中应用；启动插件不会再重复写入宿主或 profile 文件。此次改动可避免插件自身在每次启动时触发写入，但不会替代 `dsh-purge` 的上游修复。若升级后仍循环，请保留相关启动日志并确认实际启用的 `dsh-purge` 版本与 profile。
